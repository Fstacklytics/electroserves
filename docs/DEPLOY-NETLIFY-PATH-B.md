# Path B — Netlify Static Deployment (Astro + Tailwind + Alpine + Decap CMS)

**Status:** Path B is the canonical deployment path. It **replaces**
the Nginx + PHP-FPM + Ubuntu runtime described in `deploy/README.md` and
`deploy/nginx.conf` (both removed) and supersedes the "supported deployment"
section of `docs/DEPLOY-VERCEL-ASSESSMENT.md` for this repository.

> For the full current-architecture reference (rendering, content collections,
> Decap CMS / Netlify Identity flow, CSP details, and the repo-vs-dashboard
> split), see **[`docs/ARCHITECTURE.md`](ARCHITECTURE.md)**.

---

## What changed

The Laravel / PHP runtime is gone. The site is a **fully static Astro build**:

| Layer | Old (Nginx + PHP-FPM) | Path B (Netlify) |
|---|---|---|
| Language | PHP 8.3 | TypeScript / JavaScript (Astro) |
| Framework | Laravel 11 | Astro 4.x static |
| Template | Blade | Astro components |
| CSS | Tailwind 3.4 | Tailwind 3.4 (same tokens) |
| JS | Alpine 3.14 | Alpine 3.14 (same components) |
| CMS | Decap CDN + GitHub OAuth | Decap CDN + Netlify Identity + Git Gateway |
| Content | read + parsed at request time | parsed once, at build time |
| Forms | Laravel Mail + 5/hour cache limiter | Netlify Forms + honeypot |
| Hosting | Nginx + PHP-FPM 8.3 on Ubuntu 22.04 | Netlify (CDN + build) |
| Headers | `SecurityHeadersMiddleware` + Nginx | `netlify.toml` headers |

**Stays:** every Markdown/YAML content file, the Tailwind design tokens, the
Alpine components, the Decap collection definitions, and the SEO structure.
**Goes:** `app/`, `bootstrap/`, `config/`, `routes/`, `composer.json`, the
PHPUnit suite, file sessions, the file-backed response cache, and the PHP
mailer / rate limiter.

## Why this resolves the Vercel blockers

`docs/DEPLOY-VERCEL-ASSESSMENT.md` recorded six reasons the old codebase could
not run on a stateless platform. Path B removes each one because **there is no
server runtime at all**:

1. **File-backed sessions** — eliminated. No sessions, no CSRF state server-side.
2. **File-backed response cache** — eliminated. Every page is pre-rendered to
   static HTML; there is nothing to cache at request time.
3. **Request-time Markdown parsing** — eliminated. Content is parsed and
   validated **once at build** (`src/lib/content.ts` + `@astrojs/markdown-remark`).
4. **Discarded Nginx hardening** — replaced by response headers in
   `netlify.toml` (CSP, `X-Frame-Options`, `X-Content-Type-Options`,
   `Referrer-Policy`) and immutable caching for hashed assets.
5. **Ephemeral logs** — moot. There is no runtime to log; build output is
   captured by Netlify.
6. **Cache-backed 5/hour rate limiter that fails open** — replaced by Netlify
   Forms with a **honeypot** (`bot-field`) and HTML5 required validation, which
   needs no shared state.

## The trade-off being accepted

Moving to static hosting trades the old runtime for managed infrastructure.
What you give up:

- **No per-request dynamic logic.** Every page is generated at deploy time, so
  anything content- or date-dependent only updates on a rebuild. Content edits
  via the CMS trigger a Netlify build, so published changes appear after that
  build completes (not instantly at request time).
- **Contact form is now a Netlify Form**, not an email generated by the app.
  Submissions are collected by Netlify and forwarded to the configured inbox.
  The 5/hour per-IP app-level limiter is gone; spam protection relies on the
  honeypot plus Netlify's own spam filtering. Rate-limiting is no longer
  controllable from the repo.
- **No OPcache / response-cache tunables.** The old `CONTENT_CACHE_*` and
  `RESPONSE_CACHE_*` env vars and `content:flush` / `responsecache:clear`
  commands are removed. Cache behaviour is governed by `netlify.toml`.
- **CMS auth moved from GitHub OAuth to Netlify Identity + Git Gateway.**
  Enabling it is a Netlify UI step (below), not a repo change. The site runs on
  Netlify's **free Starter plan**, which is sufficient for the normal CMS
  workflow: Identity supports up to 5 registered users, Git Gateway and Netlify
  Forms are included within Starter usage quotas, and no plan upgrade is
  currently required. Beyond 5 editors Netlify charges per seat.

What you gain:

- **Zero server administration.** No Nginx config, no PHP-FPM pool, no Ubuntu
  patching, no Let's Encrypt renewal, no releases/`current` symlink runbook.
- **Global CDN, automatic TLS, immutable-asset caching** out of the box.
- **Content edited in the CMS opens a PR** (editorial workflow) and deploys a
  preview before merging.
- The five-year-old file-backed session/cache complexity is deleted, which is
  the point of the redesign.

## How to deploy

1. Push `main` (or open a PR) to GitHub.
2. In Netlify: **New site from Git** → pick this repo → build command
   `npm run build`, publish directory `dist` (these are already in
   `netlify.toml`).
3. In the **Site settings → Identity**: enable Netlify Identity, then enable
   **Git Gateway** (needs a GitHub account with repo access), then **Invite
   editors**.
4. Editors open `/admin` on the deployed site, sign in with Netlify Identity,
   and manage content. Because `publish_mode: editorial_workflow` is set, their
   edits open a PR that goes through normal review + build.

For local development with the CMS proxy:

```bash
npm install
npx netlify dev   # serves the site and the /admin local backend proxy
```

## Verification done / not done

**Done in this sandbox:**
- `npm run build` succeeds; `dist/` contains 27 pages.
- `dist/` CSS + JS is ~147 KB pre-gzip (well under the 500 KB budget).
- No duplicate element ids across any built page.
- Every `<img>` carries explicit `width`/`height` and `loading` (lazy, except
  the first hero slide which is eager with `fetchpriority="high"`).
- Every page has exactly one `<h1>`, plus `header`/`main`/`footer` landmarks and
  a skip-to-content link.
- The contact form is present in the built HTML with `name="contact"`,
  `data-netlify="true"`, `netlify-honeypot="bot-field"` and the hidden
  `form-name` input, so Netlify detects the form.
- Content integrity: 6 services, 6 projects, 4 blog posts, 6 testimonials,
  5 team members, 10 FAQs and 3 hero slides all render.

**Cannot be verified in this sandbox (label as NOT verified):**
- A real Netlify deploy (no Netlify account here).
- The Netlify Identity email-flow / Git Gateway login end-to-end.
- A real browser screen-reader / keyboard pass (no browser in the sandbox).
- Netlify's actual form-submission and honeypot behaviour in production.

Run `netlify deploy` from a Netlify CLI-authenticated machine to confirm the
build, and click through `/admin` once Identity + Git Gateway are enabled.
